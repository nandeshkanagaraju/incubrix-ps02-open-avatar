**Why DINOv2 for identity, not CLIP?** The adherence metric already uses CLIP.
Scoring identity with the same family would let one model both describe and
grade the output. DINOv2 is a self-supervised backbone trained with a different
objective and is not part of the generation stack, so it provides an
*independent* embedding view, as the brief requires.

## Datasets and media

**None used.** No dataset was downloaded, no model was fine-tuned, and no
third-party media is redistributed in this repository. Every image in
`evidence/` was generated by this pipeline from the committed specs.

## Reference images / personal data

`consent/reference_images/` is git-ignored and empty in this repository. No
identifiable person's likeness is committed. The consent registry stores SHA-256
hashes and a pseudonymous `subject_ref` only — never image bytes and never a
legal name. See README → "Consent and privacy controls".

## Attribution obligations

- **CreativeML OpenRAIL-M / openrail++ (`sd15`, `sd15_lcm`)** — the licence and
  its use restrictions must be passed downstream to any recipient, and the
  restrictions in Attachment A must be reproduced in any derived service terms.
  The restrictions this project must honour operationally (no minors, no sexual
  content, no impersonation, no discriminatory targeting) are enforced in
  `safety.py` rather than left to documentation.
- **Stability AI Non-Commercial Research Community License (`sdturbo`)** — no
  commercial use. It is configured as a comparison model and is flagged
  `"commercial_use": "NOT permitted - research comparison only"` in
  `configs/default.json` so the restriction travels with the config.
- **Apache-2.0 libraries** — retain NOTICE/licence text on redistribution.

## Product recommendation

**Preferred commercially reusable stack:** `sd15` + `sd15_lcm` (OpenRAIL-M /
openrail++) on the local orchestrator, with DINOv2 (Apache-2.0) for identity
scoring. Both permit commercial use subject to use restrictions that this
codebase already enforces in the safety layer.

**Research-only, must not ship:** `sdturbo`. CLIP (MIT) is fine to ship but is an
evaluation dependency, not a product dependency.

**Unresolved before product use:**
1. OpenRAIL-M use restrictions must be mirrored into customer-facing terms; this
   is a legal review item, not an engineering one.
2. SD 1.5 was trained on LAION-5B. Training-data provenance and the resulting
   likeness/copyright exposure is unresolved industry-wide and needs a
   jurisdiction-specific opinion before commercial launch.
3. Individual-avatar work needs a retention schedule and a DPIA; the
   `consent purge` control implements deletion but no retention policy is set.
4. Synthetic-media labelling currently lives in `avatar_manifest.json`. Shipping
   would want C2PA content credentials embedded in the image files themselves.
